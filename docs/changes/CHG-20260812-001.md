# CHG-20260812-001 — Repository-first Agent and Architecture Governance

## Impact Analysis

- CHANGE_ID: CHG-20260812-001
- Requested Change: 使用六个固定逻辑 Agent，以仓库产品/技术架构和 ADR 作为持久项目记忆，引入 C0–C3 门禁。
- Current Architecture: 变更前只有 feature 文档和六个细分执行技能；`AGENTS.md` 明确禁用 architecture-first，缺少全局当前产品/技术架构。
- Affected Product Domains: 全产品治理，不改变运行时用户能力。
- Affected Technical Components: `AGENTS.md`、`agent-skills/`、`docs/`。
- Existing Owner Module: 根治理文件；无独立 architecture-agent。
- Data Model Impact: 无。
- API Impact: 无。
- Permission Impact: 无运行时影响；新增 Agent 文件所有权和审批规则。
- Tenant Impact: 无运行时影响；治理明确所有变更必须验证 tenant isolation。
- Integration Impact: 无外部运行时影响。
- Backward Compatibility: 保留已有 `docs/features/` 和业务代码；旧角色技能被新六角色替代。
- Potential Coupling: 文档、Agent 启动和 Change/feature 流程产生显式依赖，这是预期治理依赖。
- Circular Dependency Risk: 低；产品定义 WHAT，architecture 定义全局 HOW，实现角色不能反向静默改架构。
- Migration Required: 仅文档/技能迁移，无数据库迁移。
- Coupling Level: C3（治理核心假设变化）。
- Architecture Change Required: YES。
- Recommended Integration Strategy: 建立完整当前架构基线；更新治理；创建六个角色技能、边界、QA、ADR 和 changelog；保留现有 feature 证据。
- Rejected Integration Strategies: 仅把附件追加到旧 AGENTS；仅创建 architecture-agent 而不建立事实文档；依赖固定 Agent thread 保存记忆。
- Reason: 上述方案会保留冲突规则或继续产生文档漂移。
- Implementation Dependencies: 只依赖当前仓库只读盘点，无业务实现依赖。

## Approved Architecture

仓库文档是持久记忆；固定逻辑角色为 product/architecture/backend/frontend/qa/e2e；C2/C3 必须先审架构。物理 nickname 仅用于当前执行实例。

## Implementation Plan

- Affected Files: `AGENTS.md`、`agent-skills/*`、`docs/product`、`docs/architecture`、`docs/backend`、`docs/frontend`、`docs/qa`、`docs/changes`。
- Database Changes: 无。
- API Changes: 无。
- Frontend/Backend Changes: 无业务代码变化。
- Migration: 新角色技能替代旧逻辑技能；已有 feature 文档继续有效。
- Compatibility Requirements: 不删除 feature 历史；保留单 Agent、文件所有权、安全和不部署生产规则。
- Implementation Sequence: 治理 → 当前架构基线 → ADR/changelog → 边界/QA → Agent 技能 → 静态校验。
- Tests Required: 文档存在性、链接/角色名搜索、禁止冲突规则搜索、`git diff --check`。
- Regression Scope: 仅治理与文档，无运行时测试。
- E2E Scope: 不适用。
- Rollback Strategy: 通过 Git 恢复本 Change 的文档 diff；不涉及数据库或部署。
