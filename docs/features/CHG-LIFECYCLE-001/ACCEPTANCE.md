# 验收标准

1. 测试阶段站点生命周期由 `is_active` 映射为 `active / archived`，只允许归档和恢复；本阶段不返回 `closing`。
2. 测试阶段充电桩生命周期以现有 `is_active` 映射为 `active / retired`；退役写操作同时设置 `commissioning_status=suspended`，恢复只允许 `retired → active` 且恢复后 `commissioning_status=testing`，本阶段不返回 `retiring`。
3. 退役原因和归档原因去除首尾空格后必须为 3–500 字符。
4. 无进行中会话的充电桩发起退役后直接变为 `retired`。
5. 测试阶段有进行中会话或未完成必要账务的充电桩发起退役返回 `409 charger_retirement_blocked`，当前会话和设备数据不被修改。
6. 会话和必要账务完成后可重新发起退役，并幂等地进入 `retired`。
7. `retired` 设备的旧 OCPP 凭据不可再建立连接，关联二维码不可再发起充电。
8. `retired` 设备不出现在站点正常详情，不计入可运营/在线数量，也不出现在 App、地图和正常可绑定列表。
9. 退役设备可在独立资产归档接口和 Admin 页面查询，并显示原站点、退役原因、退役时间和操作人。
10. 退役不得删除设备、EVSE、历史会话、计量、订单、发票、支付、告警、事件、验收报告或审计数据。
11. 站点归档预检返回正常桩、退役桩、进行中会话和未完成账务的结构化数量及阻塞项；测试阶段 `retiring_charge_points` 固定为 0。
12. 站点存在 `active` 充电桩时归档返回 `409`，不得自动删除或迁移设备。
13. 站点仅包含 `retired` 充电桩时允许归档；退役桩仍保留原 `site_id`，但不在站点正常页面显示。
14. 归档站点不出现在 App、地图、默认 Admin 站点列表和正常运营统计中，可通过归档筛选查询。
15. 恢复归档站点不会自动恢复其退役充电桩。
16. 测试阶段充电桩迁移只允许同一租户内、目标为活动站点，且源设备没有进行中会话、历史会话或订单；跨租户、目标归档或存在业务历史均返回 `409` 或 `403`。
17. 因测试阶段不增加历史站点快照，任何存在历史会话或订单的充电桩都不能迁移，历史站点归属不得被改写。
18. 充电桩永久删除仅允许未投运草稿且无任何业务/设备历史的记录，否则返回 `409` 及稳定的 `blockers`。
19. 站点永久删除仅允许完全未使用且无任何正常或退役设备、业务、定价和公开使用记录的站点，否则返回 `409` 及稳定的 `blockers`。
20. 永久删除的 `confirmation` 与资源公开标识不一致时返回 `422`，不得修改数据。
21. 生命周期读取要求 `sites.read`/`chargers.read`，写操作要求 `sites.write`/`chargers.write`；无权限返回 `403`。
22. 普通管理员不能读取或修改其他租户的活动或归档资产，伪造请求体或查询参数中的 `tenant_id` 不得绕过隔离。
23. 退役、恢复、归档、迁移和永久删除均写入包含操作者、租户、资源、原因、前后状态和 UTC 时间的审计日志。
24. 退役完成、归档完成和恢复接口具备幂等行为；重复请求不重复撤销凭据、重复写业务副作用或改变历史数据。
25. Admin 站点详情有“归档站点”预检流程，充电桩详情有“退役充电桩”流程，危险操作均有明确确认和错误提示。
26. Admin 正常站点页面不渲染退役桩；资产归档页面可以查看和筛选退役桩及归档站点。
27. 后端定向 API、状态迁移、租户隔离、历史归属测试和 Admin 聚焦组件/集成测试通过。
28. 本轮实现不新增 Alembic revision，不修改数据库表结构；归档/退役原因、操作者和时间可从现有审计日志追溯。
