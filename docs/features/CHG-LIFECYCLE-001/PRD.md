# 站点归档与充电桩退役生命周期

## 背景

当前 Admin 没有站点删除入口，充电桩也没有面向运营人员的退役入口。后端虽然已有站点和充电桩 `DELETE` 接口，但站点接口只检查是否存在充电桩，充电桩接口会直接物理删除记录，未覆盖进行中会话、订单、账务、OCPP 凭据、二维码、告警和审计等生产约束。

成熟充电运营平台通常区分归档、停用、迁移和永久删除：归档资产从司机端及日常运营列表隐藏，但保留历史；永久删除只用于误创建且从未投入运营的数据。站点与充电桩的可见性、实时状态和资产生命周期不能使用同一个布尔字段混合表达。

参考：

- [Virta](https://support.virta.global/hc/en-gb/articles/15854054679197-How-to-Archive-and-Delete-Charging-Points-and-Pools)：归档充电点后从 App 隐藏并停止使用，充电点不可永久删除；Pool 只有在包含归档充电点在内都为空时才可永久删除。
- [Zaptec](https://help.zaptec.com/installation/remove-move-or-replace-a-zaptec-charging-station-in-the-zaptec-portal)：停用、移除设备、迁移、替换和永久删除为不同操作；停用保留配置及充电历史。
- [SAP E-Mobility](https://help.sap.com/docs/SAP_E_MOBILITY/bd7718e8240e4005809ec06621881bd2?locale=en-US&state=PRODUCTION&version=CLOUD)：设备应保持站点归属，迁移到其他站点，不产生无归属运营设备。
- [Tridens](https://tridenstechnology.com/ev-charge-web-docs/stations/)：公开可见性与运营状态分离；迁移站点可能影响历史会话和漫游归属。

## 目标

- 测试阶段使用现有字段提供站点 `active / archived` 生命周期，并为生产阶段预留 `closing`。
- 测试阶段使用现有字段提供充电桩 `active / retired` 资产生命周期，并为生产阶段预留 `retiring`。
- 退役充电桩不出现在站点正常详情、App、地图、二维码入口和正常运营统计中。
- 退役充电桩保留原站点关系及所有历史业务数据，并可在独立资产归档入口查询。
- 站点存在正常或退役中充电桩时禁止归档，运营人员必须先迁移或退役设备。
- 站点仅包含退役充电桩时允许归档，但禁止永久删除。
- 测试阶段有进行中会话时拒绝退役；生产阶段再支持进入 `retiring` 并在会话及账务完成后自动转为 `retired`。
- 永久删除只对误创建、未投运且不存在业务历史的记录开放。
- 所有退役、恢复、归档、迁移和永久删除操作按租户隔离并写入审计日志。
- 设备迁移或退役不得改变历史会话、订单和账单的原站点归属。

## 核心产品规则

### 测试阶段实施约束

- 本阶段不新增 Alembic 迁移，不修改数据库表结构。
- 站点对外生命周期由现有 `Site.is_active` 映射：`true → active`、`false → archived`；本阶段不产生 `closing`。
- 充电桩对外生命周期以现有 `is_active` 映射：`true → active`、`false → retired`；退役写操作同时强制 `commissioning_status=suspended`，兼容旧的非活动设备并确保其不会重新暴露。本阶段不产生 `retiring`。
- 归档/退役原因、操作者和 UTC 时间写入现有 `AuditLog`，归档查询从最新对应审计记录读取这些信息。
- 存在进行中会话时退役返回阻塞，不进入异步退役；运营人员需结束会话和必要账务后重试。
- 没有历史站点快照前，存在任何历史会话或订单的充电桩禁止迁移，避免历史报表归属被当前 `site_id` 改写。
- `closing`、`retiring`、生命周期专用字段和历史站点快照属于生产阶段迁移目标，不属于本轮测试实现。

### 生命周期与实时状态分离（生产目标）

- 站点生命周期：`active`、`closing`、`archived`。
- 充电桩资产生命周期：`active`、`retiring`、`retired`。
- 现有 `commissioning_status` 继续表示 `draft / testing / ready / commissioned / suspended`，不得用 `suspended` 代替永久退役。
- OCPP/EVSE 的 `Available / Charging / Offline / Faulted` 等仍是实时状态，不表示资产是否退役。
- 上述完整状态是生产目标；测试阶段使用前述现有字段映射并保留相同业务语义。

### 退役充电桩

- 操作者必须填写 3–500 字符的退役原因。
- 发起退役后立即禁止新订单、扫码启动、远程启动、预约和新 OCPP 认证。
- 无进行中会话时直接进入 `retired`。
- 生产目标允许有进行中会话时进入 `retiring` 并在结算后自动完成。测试阶段因不增加持久化字段，存在进行中会话时拒绝退役，待会话和必要账务完成后重试。
- 进入 `retired` 时撤销设备凭据、使二维码失效、将 EVSE 置为不可用于新业务并记录审计日志。
- 退役不会删除充电会话、计量、订单、账单、支付、告警、设备事件、验收报告或审计记录。
- 退役桩保留 `site_id`，但站点正常详情及正常计数必须排除 `retired`。生产阶段的 `retiring` 设备继续显示在 Admin 站点详情并明确标记“退役中”，但不计入可运营/在线数量。

### 恢复退役充电桩

- 仅具备 `chargers.write` 权限的当前租户管理员或超级管理员可以恢复。
- 恢复后资产生命周期回到 `active`，投运状态回到 `testing`，不能直接恢复为 `commissioned`。
- 必须生成新的设备凭据并重新完成验收和投运，旧凭据不得恢复。
- 恢复操作写入审计日志。

### 归档站点

- 归档预检必须返回正常桩、退役中桩、退役桩、进行中会话和未完成账务数量。
- 测试阶段存在 `active` 充电桩时禁止归档；生产阶段存在 `active` 或 `retiring` 充电桩时禁止归档，并返回可处理的阻塞项。
- 运营人员应对正常桩逐台选择迁移到同租户其他活动站点，或发起退役。
- 仅包含退役桩或完全没有充电桩时允许归档。
- 归档站点从 App、地图、默认 Admin 列表和正常运营统计隐藏，但历史记录仍可按原站点查询。
- 归档站点可以恢复；恢复不自动恢复退役桩。

### 永久删除

- 充电桩永久删除仅允许：`commissioning_status=draft`、资产生命周期为 `active`、从未正式投运、无连接会话、无充电会话、无订单、无账务支付、无告警、无设备事件、无待执行指令且无必须保留的审计关联。
- 站点永久删除仅允许：无正常/退役/退役中充电桩、无历史业务、无定价历史、无收藏或公开使用记录，且从未进入归档运营流程。
- 不满足永久删除条件时返回 `409` 和结构化阻塞项，不得级联删除业务历史。
- 永久删除必须二次确认，提交与资源公开标识一致的 `confirmation`，并写入审计日志。

### 历史归属

- 充电会话和订单创建时保存不可变的站点快照，至少包括 `site_id`、`site_code` 和站点名称快照。
- 历史报表、交易和账务按快照归属，不通过充电桩当前 `site_id` 反推历史站点。
- 在历史快照完成前，不得放宽现有充电桩迁移能力以处理有历史业务的设备。
- 测试阶段通过“存在历史会话或订单即禁止迁移”满足该约束，不回填或改表。

## Admin 交互

### 站点详情

- 操作菜单提供“归档站点”。
- 点击后先展示归档预检：正常桩、退役中桩、退役桩、进行中会话和未完成账务。
- 存在正常桩时，提供“迁移到其他站点”和“退役充电桩”的明确入口，不提供强制级联删除。
- 满足条件后允许确认归档。
- 仅满足严格永久删除条件时，在危险操作区显示“永久删除站点”。

### 充电桩详情

- 正常运营设备提供“退役充电桩”。
- 有进行中会话时明确说明将进入“退役中”，不会中断当前充电。
- 草稿且满足严格条件时才显示“永久删除设备记录”。
- `retired` 设备不出现在站点详情的正常充电桩列表；生产阶段的 `retiring` 设备继续显示并提供退役进度，避免资产在流程完成前失去管理入口。

### 资产归档

- Admin 增加独立归档入口，包含“已归档站点”和“已退役充电桩”。
- 支持按原站点、公开编号、OCPP Identity、原因和时间筛选。
- 退役桩详情显示原站点、退役时间、原因、操作人及历史数据入口。

## 权限与租户隔离

- 查看归档资产沿用 `sites.read` 或 `chargers.read`。
- 归档/恢复站点和永久删除站点要求 `sites.write`。
- 退役/恢复充电桩和永久删除充电桩要求 `chargers.write`。
- 后端从认证租户上下文确定资源范围，不接受请求体中的 `tenant_id` 作为授权依据。
- 超级管理员执行租户资源操作时仍必须明确有效租户上下文或使用受审计的超级管理路径。

## 非范围

- 不自动执行现场断电、锁定挂牌或物理拆除。
- 不在本需求中实现跨租户迁移。
- 不复用已退役设备的旧 OCPP 密钥。
- 不通过级联删除清理历史交易、账务、计量、告警或审计数据。
- 不改变 OCPP 协议版本或设备厂商现场配置方式。
- 不部署生产环境，不迁移生产数据。

## 成功指标

- 日常站点和 App 查询中不出现退役桩。
- 退役、迁移和归档后历史交易站点归属保持不变。
- 不再发生通过设备或站点删除误删历史业务数据的情况。
- 所有生命周期变更均可通过审计日志追溯。
