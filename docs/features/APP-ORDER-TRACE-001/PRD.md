# App 充电订单与钱包扣费统一追溯

## 问题

- 充电历史详情只展示协议和计量信息，没有展示最终消费金额。
- 钱包中的充电扣费流水不能进入对应的充电订单详情。
- 终端用户页面暴露 OCPP 交易号和数据库充电桩 ID，无法帮助用户理解订单。

## 目标

- 最终金额以 `Invoice` 为唯一权威来源，App 不自行计算费用。
- 钱包充电扣费与对应的充电会话建立明确关联。
- 充电历史和钱包共用同一订单详情页面。
- 用户详情展示业务账单号、站点、充电设备、枪口、时间、电量、时长、最终金额、币种和支付状态。
- OCPP 交易号、OCPP 身份和数据库 UUID 不展示给终端用户。

## 产品规则

- `charge` 类型钱包流水有且仅有明确关联充电会话时才可进入订单详情。
- `top_up`、`refund`、`adjustment` 等非充电流水本期不进入充电订单详情。
- 未完成结算的会话显示“待结算”，不显示推算金额。
- 已结算金额使用账单 `total_amount`；币种由服务端返回，本期为 `COP`。
- 枪口显示物理标签；缺失时使用国际化“枪口 {number}”。

## 非范围

- 不实现充值、退款或人工调整流水的独立详情页。
- 不修改计价规则、钱包余额算法或支付状态机。
- 不处理搜索框布局和外部地图导航。
