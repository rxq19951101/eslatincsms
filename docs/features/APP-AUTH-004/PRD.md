# App 过期会话退出登录循环修复

## 问题

App 启动时仅以 access token 是否存在判断登录状态。过期会话触发 401 后，API 层会清除本地 Token 并重置到欢迎页，但 Redux 仍保持已登录，残留请求可能再次重置导航，导致用户进入邮箱登录页后立即返回欢迎页。

## 产品规则

- 启动恢复会话时不得将明确过期且无法刷新的 Token 视为已登录。
- access token 过期时优先使用 refresh token 恢复；刷新失败或缺少 refresh token 时完整退出本地会话。
- 会话失效必须同步清除 Token、缓存用户和 Redux 登录状态。
- 同一批并发 401 只能触发一次会话失效和一次欢迎页导航重置。
- 认证公开接口的 401 不得触发刷新或全局退出循环。
- 用户进入邮箱登录页后，不得再被旧会话的残留请求重置回欢迎页。

## 非范围

- 不修改后端登录、刷新 Token 或密码规则。
- 不改变登录页面视觉和文案。
- 不调整登录后的业务导航流程。
