# 显式充电定价模式与商业投运门禁

## 问题

- 当前充电桩可以在没有有效 Tariff 时保持业务可用，甚至进入扫码启动流程。
- `0`、未配置和免费没有明确区分，存在误免费或结算失败风险。
- 草稿充电桩可能出现在 App；投运验收不要求有效定价。
- App、Admin、扫码检查和结算分别查询 Tariff，优先级和有效期规则不一致。
- 价格快照在结算时才创建，充电过程中改价可能影响进行中的会话。

## 目标

- 面向业务明确区分 `paid`、`free`、`unavailable`。
- 免费必须由有权限的运营人员主动选择，并填写原因和截止时间。
- 充电桩覆盖定价额外支持 `inherit`，用于继承站点默认定价。
- 没有明确可用价格的充电桩不得正式投运、公开展示或开始新会话。
- 所有消费者使用同一个有效定价解析服务，固定优先级为充电桩覆盖价优先、站点默认价其次。
- 会话开始时固化价格快照，后续改价不影响进行中的会话。

## 产品规则

### 定价模式

- `paid`：司机承担费用；`base_price_per_kwh` 必须大于 0。
- `free`：司机支付 `0 COP`，成本由运营方或合作方承担；必须提供 `free_reason` 和未来的 `valid_until`。
- `unavailable`：未完成商业定价或暂不提供商业服务；不得开始新会话。
- `inherit`：仅用于充电桩覆盖定价，删除当前覆盖语义并继承站点默认定价。
- 新建站点和充电桩的有效模式默认是 `unavailable`。
- 旧 Tariff 仅在价格大于 0 时兼容识别为 `paid`；没有显式模式的零价旧记录识别为 `unavailable`，不得自动变成免费。

### 免费充电

- 免费原因长度为 3-500 个字符。
- 免费截止时间必须晚于当前时间；到期后自动解析为 `unavailable` 或回退到下一层有效定价。
- 免费会话仍创建订单、价格快照、账单、支付审计和能耗记录，最终金额为 `0 COP`；由于钱包没有发生金额变化，不创建 0 金额钱包变动流水。
- 免费设置、取消和到期必须可审计。

### 分层和有效价格

- 解析顺序：当前有效的充电桩覆盖规则 → 当前有效的站点默认规则 → `unavailable`。
- 显式的充电桩 `unavailable` 覆盖站点价格，防止特定设备继续商业运营。
- 同一层级同时存在多条匹配记录时，使用 `valid_from` 最新的一条；写接口必须关闭旧的当前规则。
- App、Admin、投运、扫码检查、启动和结算不得自行实现第二套 Tariff 查询。

### 投运和公开

- 正式投运要求验收通过，且有效定价模式为 `paid` 或 `free`。
- App 公开列表只返回站点有效、充电桩有效、`commissioning_status=commissioned` 且有效定价为 `paid/free` 的设备。
- Admin 可继续查看 `unavailable` 设备，并显示阻断原因。
- OCPP 设备在线与商业可用是两个独立状态；`unavailable` 不要求断开设备连接。

### 启动和结算

- 扫码检查和启动都必须解析有效定价；`unavailable` 返回稳定业务错误 `TARIFF_NOT_CONFIGURED`。
- 会话创建时创建 `PricingSnapshot`，保存模式、COP 单价、服务费、规则和来源 Tariff。
- 结算必须优先且正常情况下仅使用会话价格快照。
- 对没有快照的历史会话，只允许按 `session.start_time` 解析当时所属桩/站点价格；禁止使用租户任意 Tariff 兜底。
- 进行中的会话不受后续价格修改影响。

## 数据兼容策略

- 本需求不新增数据库迁移。
- 显式模式和免费元数据存入 Tariff 现有 `time_based_rules` JSON：`schema_version`、`pricing_mode`、`free_reason` 和可选 `rules`。
- 继续兼容旧的时段规则数组；新结构中的 `rules` 保存时段规则数组。
- `base_price_per_kwh`、`service_fee`、`valid_from`、`valid_until` 继续使用现有列。

## 非范围

- 不实现会员、车队、漫游和合作伙伴差异化价格组。
- 不实现动态电价、占位费、最低/最高费用和税务计算。
- 不修改生产数据，不部署生产环境。
