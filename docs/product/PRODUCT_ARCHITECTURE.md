# EsLatin 当前产品架构

> 状态：current baseline  
> 基线日期：2026-08-15
> 维护角色：product-agent

## 1. 产品目的

EsLatin 是面向哥伦比亚充电运营场景的多租户充电运营平台。系统连接充电桩、运营人员与终端车主，提供站点和设备运营、扫码充电、定价计费、支付、钱包、订单、告警、审计与模拟测试能力。

## 2. 用户与参与方

- 车主/App 用户：发现公开站点和充电桩、扫码、选择支付方式、启动/停止充电、查看会话、钱包与订单。
- 租户管理员：管理本租户站点、充电桩、价格、成员、交易、告警和配置。
- 平台超级管理员：跨租户平台治理、租户与平台级运营管理。
- 充电桩：通过已批准的 OCPP 身份连接平台并上报状态、会话和计量数据。
- 支付服务商：当前产品唯一启用 Mercado Pago。App 不暴露 Provider 选择；未来支付方式只能通过服务端 Provider Adapter/Registry 接入。
- 模拟器/测试运营人员：使用 charger-sim 和测试种子验证 OCPP、充电与支付旅程。

## 3. 产品领域

### 身份、租户与权限

- 区分 Admin 与 App 用户身份和令牌受众。
- Admin 通过租户成员关系和角色权限访问运营数据。
- 超级管理员可执行平台范围操作；租户管理员不得跨租户访问。

### 站点与资产生命周期

- 站点组织地址、位置和充电资产。
- 充电桩、EVSE/connector、设备及其状态属于租户。
- 退役充电桩不出现在正常站点运营列表，但保留历史会话、订单、账务和审计关联。
- 含有效充电资产或历史约束的站点不能被无条件物理删除；生命周期操作必须保持历史完整性。

### 公共发现与 App

- App 用户可查看公开站点、位置、价格和可用充电资源。
- 支持地图、站点详情、收藏、扫码/手动 QR token、账户和多语言界面。

### OCPP 与设备运营

- 当前生产边界以 OCPP 1.6J WebSocket 为已确认协议。
- 设备连接需预注册身份和凭据；连接状态、心跳、状态通知、远程启动/停止、充电会话和计量值构成运营主链路。
- 高频遥测采用实时状态与采样持久化策略，避免每次心跳/计量都形成无界数据库写入。

### 定价、会话、账单与订单

- 价格模式为 `paid`、`free`、`unavailable`。
- paid 会话按已冻结价格快照结算；free 生成零金额审计事实；unavailable 不允许启动。
- 充电会话、Invoice、Payment、Order 使用明确状态和关联，历史金额事实不可由后续价格修改覆盖。
- 金额以 COP 十进制定点语义处理。

### 钱包与支付

- App 钱包支持余额、充值和交易记录。
- 支付产品包含独立添加银行卡、单次新卡消费、已保存卡消费、钱包充值和退款/对账基础能力。
- 新卡直接充电固定只用于本次消费，不在同一流程保存。
- 保存银行卡通过独立 `save_card` Checkout 完成；后续使用保存卡时重新采集 CVV。
- 卡品牌、issuer 和 credit/debit/prepaid 类型由支付服务商识别，用户不手动选择；旧未知类型显示为通用银行卡。
- 哥伦比亚支付服务商要求的证件类型/号码只在 Mercado Pago 安全托管页与 SDK 边界内处理，不进入 EsLatin App API、数据库或日志。
- Hosted Checkout Session 自创建起有效 `10` 分钟，由服务端 `expires_at` 作为唯一过期事实；托管页显示剩余时间，剩余 `2` 分钟进入警告态，过期后隐藏/禁用卡表单并拒绝提交。
- App 不对支付结果进行无限后台轮询：原充电页在支付页返回、浏览器重新获得焦点、App 回到前台或用户主动查询时读取同一 Checkout Session；所有自动查询必须有明确上限。会话过期后清理待恢复引用并引导用户重新开始，已提交且仍在 Provider 处理中的会话保留原引用并继续查询/恢复，不创建第二个 Checkout。
- 当前收费主体为 EsLatin 平台统一收款（C1），商户解析边界为未来 C2 多商户/分账预留，但 C2 尚未上线。
- 用户存在欠费时禁止开始新的收费充电；PAY-MP-002 的后端财务事实、资格判断和最终事实解锁已有实现/QA 证据，但 App 欠费列表、完整补缴体验和跨模块 E2E 尚未完成。
- PAY-MP-002 的历史首发范围是 App 内基础充电历史/详情及支付结果，不包含 PDF/下载/邮件收据或 DIAN 电子发票。
- 退款采用结构化工单、不同人员双人控制的全额/部分退款和可见状态；资金返回原支付方式。
- 财务采用持续逐笔匹配与每日 EsLatin/Provider/实际资金三方对账；未解释金额差异阻止扩大发布。
- 生产安全控制分别关闭收费充电准入和支付轨；关闭不丢失进行中支付、设备和对账事实，恢复须由不同授权人员批准。

### 运营后台、告警与审计

- Admin 提供仪表盘、站点、充电桩、用户、交易、支付、价格、配置、角色、告警和统计等运营界面。
- 关键运营动作、权限变更和敏感状态变更必须形成审计事实。
- 支付支持采用上下文 App 工单和邮件通知；公开收费站点在公布营业时段必须具备实时紧急支持渠道。

### 模拟与质量保障

- charger-sim 支持单桩、手动模拟和场景化 E2E。
- 测试种子可建立本地测试用户、站点、设备和 QR token；不得依赖生产数据。

## 4. 主要用户旅程

### 扫码收费充电

注册/登录 → 扫码或输入 QR token → 校验桩、connector、在线状态与价格 → 选择钱包/新卡/保存卡 → 完成必要 Checkout → 用户明确启动 → OCPP RemoteStart → StartTransaction 绑定会话 → 计量与状态更新 → 用户/设备停止 → 生成账单 → 钱包扣款或卡扣款 → 订单完成/失败恢复。

### 独立保存银行卡

账户 → 支付方式 → 添加银行卡 → EsLatin 托管安全页 → Mercado Pago Secure Fields、证件与 BIN 识别 → 保存卡成功 → 返回 canonical 非敏感投影（品牌、类型、末四位、默认状态）。

### 运营资产管理

租户管理员登录 → 建立站点 → 添加/绑定充电桩 → 配置价格 → 监控在线与会话 → 查看账单/支付 → 退役设备或受约束地删除站点 → 保持历史和审计可追溯。

## 5. 产品关系与边界

- 站点拥有充电资产，但历史会话/订单/支付不能随站点或桩的退役而消失。
- 充电域产生用量事实；定价域提供当时价格快照；账单域计算应付；支付域只处理资金状态，不能重写用量。
- App 不持有 PAN、有效期、CVV、证件或 Provider card token。
- Admin 不作为租户授权事实来源；后端根据已认证身份和数据库成员关系裁决。
- 支付成功不自动代表设备启动成功；支付 Intent 与 OCPP 启动是受状态机约束的两个步骤。

## 6. 外部集成

- Mercado Pago Colombia：卡 Token、Customers/Cards、Payments、Webhooks、Refunds 和状态查询。
- Google Maps：Admin 站点选址与地图能力；公开前端密钥必须通过来源/API 限制保护。
- SMTP/Spaceship 邮箱：账户邮件与通知。
- Cloudflare/DNS/反向代理：域名、TLS 和流量入口；不是业务事实来源。
- OCPP 充电桩：WebSocket 设备接入。

## 7. 已确认约束

- 多租户隔离是产品基本假设。
- 生产设备默认必须预注册。
- 业务时间以 UTC 存储，按用户 locale 展示。
- 支付、Webhook、远程命令和设备事件必须幂等。
- 不导入无价值历史测试数据；schema 变更仍须遵守数据库版本治理。
- 后端 QA、E2E 和人工支付审查完成前，生产支付轨保持关闭。
- 真实支付采用 R0 沙盒、R1 生产暗启动、R2 内部真实支付、R3 封闭测试、R4 人工批准公开上线的分阶段门禁；阶段晋级不能自动发生。

## 8. 当前未完成或延期能力

- 欠费的后端财务事实、资格判断和恢复边界已有实现/QA 证据；App 欠费列表、详情、完整补缴恢复体验和跨模块 E2E 尚未完成。
- C2 多租户商户入账、分账和结算。
- 已批准的退款运营、三方对账、紧急关闭和上下文支持已有后端实现/QA 证据；完整 Admin 运营 UI、生产运行时和跨模块验证尚未完成。
- D-204-B 后付风险预算、自动停止条件和 SLA 已获产品负责人批准；它现在进入独立架构/契约/实现/QA门禁，在技术验证完成前不能进入真实资金试点。
- 可下载/PDF/邮件收据和 DIAN 电子发票未纳入当前 P0。
- Mercado Pago 真实 sandbox/3DS、设备视觉和无障碍的最终验收尚未构成生产放行证据。
